# Аккаунт гостя + переписка с хозяином (как у Airbnb)

Дата: 2026-10-25 · Автор решений: Артём (bre / Rega Rega) · Записано по итогам обсуждения.

## Зачем

Гости bre сейчас пишут хозяину в WhatsApp и Telegram. Отвечают быстро (обычно за минуту, максимум ~30 мин), но квартир пока мало. Нужно, чтобы **вся коммуникация гостя с хозяином шла внутри приложения rega rega, как у Airbnb**: гостю — одно место для всего про поездку, оператору — все переписки рядом с бронями в Rega OS, без потерь по мессенджерам, и задел на рост и других операторов (sunset и следующие).

**Успех через два месяца:** большинство гостей bre пишут через приложение, а не в WhatsApp, и ни одно сообщение гостя не остаётся без ответа.

## Что уже есть (контекст для исполнителя)

- **Гостевое приложение** = экраны сайта regarega.co (Astro, репо `~/Downloads/rega-batumi`, ветка `app-phase1` → превью `rega-app-preview.vercel.app`) в Capacitor-обёртке `~/rega-rega-ios` (TestFlight). Вкладки: гид · жильё/поездка · консьерж · профиль.
- **Режим брони**: ссылка от хозяина (`?t=<guest_token>`) → экран `app/trip` (TripScreen.astro) через анон-RPC `guest_instruction` / `guest_guide`, кэш в localStorage `rr_trip`; `TripFlag.astro` включает `html.has-trip`.
- **Консьерж** (Edge Function `concierge` в `~/rega-os-v2/supabase/functions/concierge`): с бронью — по токену, без брони — по id устройства; лимиты; лог в `concierge_messages`. Сейчас на «хозяйские» вопросы отвечает «напиши хозяину в тот же чат».
- **Заявка на бронь** с карточки квартиры: `public/apt-booking.js` → `/api/booking` (Vercel) → Telegram + таблица `bookings` (source='request'); оператор подтверждает/отклоняет в Rega OS.
- **Rega OS** (операторская, `~/rega-os-v2`, admin.regarega.co) = один код для сайта и iOS-обёртки. Вход операторов — Supabase Auth в **том же проекте Supabase** (qkzinjawtumhjbezlyog). Роли: `operator_people.role` (founder / manager / cleaner / owner / staff), `my_role()`; команда оператора — `operator_members`.
- **Пуши операторам**: Edge Function `send-push` (OneSignal, адресация по external_id = user.id), триггеры через pg_net (миграции 073–075).

## Решения Артёма

### Аккаунт гостя
1. В приложении появляется **вход для гостя**. Гид, события, консьерж и открытие брони по ссылке работают **без входа**, как сейчас.
2. **Вход нужен, чтобы:** писать хозяину (в любой момент — до брони и по брони) и **бронировать через приложение** (заявка из приложения — только после входа).
3. **Способ входа в v1 — код на почту.** SMS, Apple, Google — позже (не в этой работе).
4. **Профиль после первого входа:** имя (обязательно) + телефон или почта (хотя бы одно; почта уже известна по способу входа).
5. **Как бронь попадает в аккаунт — два пути, никакого поиска по телефону/почте:**
   - бронь сделана в приложении (вошедшим гостем) → сразу в его аккаунте;
   - бронь с Airbnb и т.п. → гость добавляет ссылку на инструкцию от хозяина (вставить или по QR) → бронь привязывается к аккаунту.

6a. **QR в квартире** = ссылка на скачивание приложения и экран «добавить бронь». В нём нет ни токена, ни кодов. Доказательство, что бронь твоя, — личная ссылка от хозяина (`guest_token`).
6b. **Одна бронь — один владелец, но поездку можно разделить.** Первый вошедший гость, добавивший ссылку, становится владельцем брони. Повторно её добавить другой аккаунт не может: ему показывается «эта бронь уже добавлена». Владелец может **добавить второго гостя** (спутника) в свою поездку, и тогда они видят одну поездку и **одну общую переписку** с хозяином. Как именно приглашать (по почте или по ссылке-приглашению), решает исполнитель.
6c. Анонимная ссылка без входа продолжает показывать коды и инструкцию, как сейчас. Переписка доступна только вошедшим владельцу и спутникам.

### Переписка с хозяином
6. **Два отдельных разговора:** консьерж (ИИ, вкладка «консьерж») и хозяин (люди). Не один общий чат.
7. **Где у гостя:** как у Airbnb — в **«поездке»** кнопка «написать хозяину · <оператор>» → переписка по этой брони. Плюс «написать хозяину» **на странице квартиры до брони** (вопрос до бронирования).
8. **Сроки:** писать можно **всегда** — до брони, до заезда, во время, после выезда (как Airbnb).
9. **Консьерж:** отвечает сам на всё, что знает (коды, wifi, адрес, город, квартиры). Если не знает и вопрос про квартиру / то, что решает хозяин → предлагает «спросить <оператора>»; по нажатию вопрос уходит в переписку с хозяином, консьерж пишет «передал, ответ придёт в поездку». Без брони — такой кнопки нет (передавать некому) — *кроме вопроса до брони со страницы квартиры, это отдельный вход.*
10. **Сторона оператора — в Rega OS, и на сайте, и в приложении** (это один код): раздел «сообщения» со списком переписок по броням/квартирам, непрочитанные, ответ из переписки.
11. **Кто видит и получает пуши:** только **основатель и менеджеры** оператора. Не уборщицы, не собственники.
12. **Пуши гостю — обязательно в v1** (ответ хозяина, подтверждение брони).

13. **Запасных каналов не нужно:** ни копии в Telegram и напоминаний оператору, ни писем гостю. Только пуши и счётчики непрочитанного.

## Решения исполнителя (Артём может поправить)
- **Rega как платформа переписку не читает.** Её видят только основатель и менеджеры оператора. Это строже, чем у Airbnb, и легко расширить позже.
- **Один человек может быть и оператором, и гостем** под одной почтой. Гостевой вход не создаёт оператора: существующий триггер `handle_new_user` (миграция 069) должен пропускать гостевые регистрации. Изменение делается осторожно, а операторская регистрация после правки перепроверяется.
- **В приложении есть «удалить аккаунт»**: Apple требует это от любого приложения с аккаунтами. Публикация в App Store — отдельное решение, а пока TestFlight и превью.
- **У квартиры без оператора или без основателя и менеджеров** кнопка «написать хозяину» скрыта: сообщение, о котором никто не узнает, хуже, чем его отсутствие.

## Не цели (в этой работе)
- Запасные каналы оповещений (Telegram-копии, напоминания, письма об ответе).
- Вход по SMS, Apple, Google.
- ИИ отвечает **внутри** переписки с хозяином от имени хозяина / предлагает хозяину черновик (как новые автоответы Airbnb) — следующий шаг, не сейчас.
- Поиск броней гостя по совпадению телефона/почты.
- Изменения заявки на сайте regarega.co (в браузере вне приложения) — остаётся без входа. *(Вывод из слов «через приложение»; Артём может поправить.)*
- Тбилиси и прочий контент.

## Анти-цели (провал, даже если работает)
- Гости продолжают писать в WhatsApp, потому что в приложении неудобно или долго (длинный вход, не доходят пуши).
- Сообщение гостя «повисло» без ответа — оператор не узнал (пуш не пришёл / не та роль).
- Гость видит чужую бронь или чужую переписку.
- Коды доступа утекают за пределы личной ссылки брони (QR в квартире не должен их содержать).

## Ограничения и риски, которые надо учесть
- **Один проект Supabase для операторов и гостей.** Регистрация гостя не должна создавать операторский профиль, давать доступ к Rega OS или ломать существующие триггеры/RLS на `profiles` и операторских таблицах. Гости — отдельная сущность/роль.
- **Почта:** встроенная почта Supabase шлёт несколько писем в час — для живых гостей нужен свой SMTP (например, Resend, бесплатно до ~3000/мес; Артём добавит DNS-записи домена regarega.co по инструкции).
- **Пуши гостю** будут только у установивших приложение (Capacitor + OneSignal, тот же сервис, что у операторов); в браузере — без пушей (или web-push — на усмотрение исполнителя). Нужна новая сборка в TestFlight.
- **Доступ к базе:** SQL-миграции и выкладку Edge Functions делает Артём (у ассистента нет прав на прод-базу/деплой функций); всё готовить как SQL-файлы + команды.
- **Репо regarega_co публичный** — никаких ключей/хуков в коде.
- **UI:** без эмодзи (иконки Tabler), один главный CTA на экран, цвет = состояние; тот же визуальный язык, что у экранов поездки и консьержа. Без «падающих» анимаций.
- **Прод regarega.co не трогать** без явного «деплой» — работа идёт на `app-phase1` и превью.

## Что на усмотрение исполнителя
- Модель данных (разговоры, сообщения, участники, связь с бронью/квартирой/оператором, отметки прочитанного), RLS, RPC.
- Как гостевая сессия Supabase уживается с текущей анонимной логикой (токен брони, `rr_trip`), как связать уже добавленную по ссылке бронь с новым аккаунтом.
- Механика «в реальном времени» (Realtime-подписка или опрос), отметки «прочитано».
- Фото во вложениях в v1 — по силам; текст обязателен.
- Как именно консьерж передаёт вопрос (формулирует ли сам, гость подтверждает текст).
- Оформление экранов (с проверкой на скриншотах, мобильная ширина).
- Порядок: сначала аккаунт гостя, затем переписка — Артём согласился делать по порядку.
